# ⚙️ 配置项详解

[← 文档索引](README.md) · [项目主页](../README.md)

安装后，在 AstrBot 的 WebUI 找到本插件并进入配置页面。

## 基础配置
| 配置项 | 说明 | 示例 |
| :--- | :--- | :--- |
| **默认开启全部群语音** | 开启后所有群聊默认启用群组级语音合成，无需逐个配置白名单或执行 `/ttg`。黑名单仍优先；`/ttg-q` 可关闭当前群的群级配音，开启状态持久化时重启保留。 | `false` (默认) |
| **群组白名单** | 自动开启群级配音的群号列表，保存后实时生效，无需执行 /ttg。 | `["123456"]` |
| **群组黑名单** | 彻底禁用语音合成功能和指令的群号列表。 | `["654321"]` |
| **TTS 服务器地址列表** | **【核心】** 填入您部署好的Genie TTS服务URL。可点击"+"添加多个。 | `https://your-name.hf.space` |
| **自动TTS输出模式** | 控制日常自动触发 TTS 时的发消息方式。`audio_only`=只发语音；`audio_and_text`=语音和原文都发；`split_audio_text`=前半段语音、后半段文字。 | `audio_and_text` |
| **LLM工具输出模式** | 控制 `genie_tts_speak` 工具调用时的发消息方式。默认纯语音，不影响自动触发频率模式。 | `audio_only` |
| **语音触发模式** | 控制 LLM 日常回复命中语音时的触发策略。 | `always` / `interval` / `random` |
| **触发间隔秒数** | `interval` 模式下，两次自动语音触发之间的最短间隔。 | `300` |
| **随机触发概率** | `random` 模式下，每次命中自动语音时的触发概率百分比。 | `30` |
| **记录翻译结果** | 将原文和最终合成文本写入 AstrBot 日志。 | `false` |
| **默认角色名** | 自动语音模式下使用的默认角色。**必须是已注册过的。** | `kisaki` |
| **默认情感名** | **固定情感模式**下使用的默认情感。 | `开心` |
| **TTS默认语言** | 默认使用的语言代码，支持 `jp`/`zh`/`en`。 | `jp` |
| **启用目标语言转换** | 外语 TTS 的总开关。开启后按“外语TTS准备方式”转换为目标语言；中文模型或模型支持原文语言时可关闭。 | `true` (默认) |
| **启用 TTS 文本清洗** | 是否在发送 TTS 前先对文本做正则清洗。 | `false` (默认) |
| **TTS 清洗正则** | 清洗使用的正则表达式，默认删除括号及其中内容。 | 默认值见配置页 |
| **TTS 超时时间** | 单次 TTS 请求的超时秒数。 | `120` (默认) |
| **参考音频泄漏防护** | 合成结果时长明显超过文本预期时丢弃并自动重试一次，用于拦截「参考音频 + 新语音」叠成一条的后端 bug。建议保持开启。 | `true` (默认) |
| **泄漏防护每字秒数** | 预期上限 = 可发音字符数 × 本值 + 停顿标记时长。越小越严格，最低 0.2。 | `0.9` (默认) |
| **泄漏防护最小基线** | 预期时长的下限，避免极短文本被误判，最低 1.0。 | `3.0` (默认) |
| **语音截断防护** | 合成结果明显短于文本应有长度时自动重合成一次，用于拦截「句段被后端漏掉、话没说完就结束」。建议保持开启。 | `true` (默认) |
| **截断防护每字秒数** | 预期下限 = 可发音字符数 × 本值（停顿不计入）。日语实测最快约 0.148s/字，默认取其一半只抓量级异常；调大更严格但可能误伤语速快的短句，上限 0.5。 | `0.10` (默认) |
| **尾部补静音** | 在成品语音末尾补一小段静音，抵消播放端（QQ 的 silk 转码等）吃掉尾帧导致的尾音被切。`0` 为关闭，上限 2000。 | `180` (默认，毫秒) |
| **开关状态持久化** | 把会话/群开关、音色选择与最近识别会话写入插件 KV 存储，重启后自动恢复。关闭则回到「重启即重置」的旧行为。 | `true` (默认) |
| **失败提示追加到回复** | **默认关**。关闭时 TTS 失败不往聊天里加任何东西，只写日志，失败详情去工作台「日志」页看；开启则在回复末尾追加一行 `(TTS失败: ...)`，方便排查但会把内部管道暴露进对话。 | `false` (默认) |

## LLM 注入与高级翻译设置
| 配置项 | 说明 | 示例 |
| :--- | :--- | :--- |
| **外语TTS准备方式** | 二选一。`llm_injection` = 主 LLM 在回复末尾直接生成 `$翻译$`，自动情感模式下也可附带 `[emotion=xxx]`；`provider_translation` = 不注入翻译标签，改由 AstrBot Provider 或外部 API 翻译。这个选择也会同步影响 `genie_tts_speak` 工具调用。 | `llm_injection` / `provider_translation` |
| **让主LLM直接生成情感标签** | 开启后，插件会向LLM注入提示词，要求其直接生成 `[emotion=xxx]` 标签。外语场景下一般与 `llm_injection` 搭配；中文直读场景也可单独开启。 | `true` / `false` |
| **注入语音工具提示** | 开启后，会向主 LLM 额外注入一段提示词，指导它只在用户明确要求“发语音/说一句/念给我听”时调用 `genie_tts_speak`。 | `true` / `false` |
| **情感注入提示词模板** | 自定义情感注入的 Prompt。`{emotions}` 占位符会被替换为可用情感列表。 | (见默认值) |
| **翻译注入提示词模板** | 仅在 `llm_injection` 时生效。用于要求主 LLM 直接给出可用于 TTS 的翻译文本。 | (见默认值) |
| **语音工具提示词** | 自定义约束 `genie_tts_speak` 何时可调用的 Prompt。支持 `{character}` 与 `{emotions}` 占位符；插件还会根据“外语TTS准备方式”自动补充：工具里该传原文，还是传翻译后的文本。 | (见默认值) |
| **AstrBot Provider** | 在 `provider_translation` 模式下优先用于翻译；自动情感识别模式下也会让它一起返回情感名。 | `openai_provider` |
| **Provider 翻译提示词** | 仅在 `provider_translation` 模式下生效，用于普通翻译场景。 | (见默认值) |

## 外语语音的推荐思路

对于日语这类外语语音，建议只在下面两种模式里选一种，不要混着开：

1. **`llm_injection`**  
   主 LLM 直接在回复末尾生成 `$...$` 翻译；如果你还开启了情感标签注入，也会一并生成 `[emotion=xxx]`。  
   这种模式下，`genie_tts_speak` 工具也会被提示“把翻译后的文本直接传进 `text` 参数”。

2. **`provider_translation`**  
   不给主 LLM 注入翻译标签，改由 AstrBot Provider 或外部翻译 API 负责翻译。  
   这种模式下，`genie_tts_speak` 工具可以直接传原文，插件会在发送前先翻译再请求 TTS。

## 性能配置
| 配置项 | 说明 | 示例 |
| :--- | :--- | :--- |
| **启用句子切分功能** | 是否开启长文本并行合成。可显著加速。 | `false` (默认) |
| **每个语音分段的句子数** | 数字越小，并行度越高，请求越频繁。请根据您的TTS服务器数量调整。 | `2` (默认) |
| **用于切分句子的正则** | **(高级)** 用于识别句子边界的正则表达式。默认已兼容中英文标点。 | `([。、，！？,.!?])` |
| **分段间停顿** | 开启句子切分后，分块拼接时按上一段的结尾标点补回停顿：句末标点/省略号补满，逗号顿号补一半，切在句中不补。0 表示不补。 | `260` (默认，毫秒) |
| **语音文本长度上限** | 超过该字数的部分**不会被朗读**（展示的文字不受影响），截断点优先选句末标点。设太小会让长回复的后半段完全没声音，设太大则分块多、排队久。`0` 表示不限制。 | `300` (默认，字符) |

## 语音收藏

这一组管 `/语音收藏` 那套指令和工作台「★ 收藏」页。

| 配置项 | 说明 | 示例 |
| :--- | :--- | :--- |
| **启用语音收藏** (`enable_voice_favorites`) | 总开关。关掉后 `/语音收藏`、`/收藏列表`、`/发收藏` 这些会直接提示已停用；`/语音转文件` 不受影响（它不往库里写东西）。 | `true`（默认） |
| **收藏上限** (`voice_favorite_limit`) | 音库最多存多少条，超出时自动淘汰最旧的**未置顶**条目。想永久留住某条就 `/收藏置顶`。范围 1~5000。 | `200`（默认） |
| **单条体积上限** (`voice_favorite_max_mb`) | 超过这个体积的音频拒绝入库，免得一条几十兆的文件把磁盘吃光。最小 1。 | `32`（默认，单位 MB） |
| **文件发送方式** (`voice_file_upload_mode`) | `/语音转文件`、`/收藏文件`、`/收藏导出` 用哪种方式把文件递出去。`auto` 先发文件消息段，失败自动退回 OneBot 上传接口；`component` 只发消息段；`onebot_action` 只走 OneBot 的 `upload_group_file` / `upload_private_file`。填了别的值按 `auto` 处理。 | `auto`（默认） |

> 收藏的音频落在 `data/plugin_data/astrbot_plugin_genie_tts_llm/voice_vault/`（`index.json` 记元信息 + `audio/` 放音频），跟临时合成缓存是两个地方，**不会被 30 分钟清理任务扫掉**。

## 日志与诊断

这一组只影响 WebUI「日志」页的数据来源。全部是**内存里的环形缓冲，不写盘**，重载插件即清空。四项都需要重载插件才生效。

| 配置项 | 说明 | 示例 |
| :--- | :--- | :--- |
| **运行日志采集** (`enable_run_log`) | 总开关。开启后插件会记下自己打的日志和每次合成的完整轨迹（LLM 原文、选中的情感与来源、耗时、失败原因）。关掉后日志页为空，也不再占内存。 | `true`（默认） |
| **运行日志条数** (`run_log_capacity`) | 内存里最多留多少条插件日志，超出丢最旧的。范围 50~5000。 | `500`（默认） |
| **合成记录条数** (`run_log_synth_capacity`) | 内存里最多留多少条合成记录。情感统计只统计还在缓冲里的记录，想看更长的趋势就调大。范围 20~2000。 | `200`（默认） |
| **记录完整文本** (`run_log_full_text`) | 开启时保存 LLM 原文与送进 TTS 的完整文本（单条上限 4000 字），方便逐字核对。关掉只留前 160 字摘要，省内存。 | `true`（默认） |

## 💡 进阶技巧

如果感觉机器人回复长文本时语音等待时间较长，可以尝试在插件配置的 **“性能配置”** 中开启 **“启用句子切分功能”**。这会显著提升长语音的合成速度，尤其是在您配置了多个TTS服务器时。理论上添加的tts服务器越多，合成长文本越快，虽然tts服务本身似乎也有切分功能，但受限于抱脸免费空间的性能，合成长文本速度还是较慢。

### 1.11.3 音频重复防护

- `tts_server_split_sentence`（默认 `false`）：控制发送给 Genie `/tts` 的 `split_sentence` 字段，独立于本地 `enable_sentence_splitting`。后端分句可能造成循环时建议关闭。
- `enable_tts_audio_repeat_guard`（默认 `true`）：有 NumPy 时使用波形近似匹配找单条语音的循环和不同文本之间相同的音频片段，重试仍异常会跳过该次发送。关闭后仍保留时长防护；没有 NumPy 时此检查自动跳过。不等同于语音识别，不能覆盖重读但波形明显不同的情况。
- `enable_tts_leak_guard`（默认 `true`）：连续两次超过时长上限时不再发送较短的一份，而是返回失败，避免已知异常音频进入 QQ。
